# 文案编译器 · Skill

一句话把需求编译成「能直接发布」的成套文案：标题、配文、备选标题、正文、互动引导、封面文案、话题标签。

## 一句话触发

用户说：

> 用文案编译器，帮我写一篇小红书的咖啡文案，语气松弛克制

或只输入触发词：`文案编译器` / `编译文案` / `写小红书文案`。

## 第一步：先把界面打开（重要）

收到触发词后，**先打开工作台界面**，让用户直接在界面里写；不要一上来就在对话里长篇输出。

| 系统 | 命令 |
|---|---|
| Windows | `start https://123212jjj.github.io/wuyu/v2/` |
| macOS | `open https://123212jjj.github.io/wuyu/v2/` |
| Linux | `xdg-open https://123212jjj.github.io/wuyu/v2/` |

打开后点「进入工作台」；登录是演示账号，随便填手机号/邮箱 + 密码即可。

> 如果运行环境不能打开浏览器，就告诉用户打开这个地址，然后按下面的模板收集需求，在对话里给出同结构结果。

## 第二步：收集需求（一次问清）

1. **写什么**：产品 / 主题 / 场景
2. **给谁看**：目标人群
3. **发哪里**：小红书 / 公众号 / 抖音 / B站（可多选）
4. **什么语气**：松弛克制 / 真诚种草 / 故事叙述 / 干货专业 / 俏皮网感
5. **必须出现或不要出现的词**

## 第三步：输出要求（与工作台生成结构一致）

每个平台单独一套，包含：

- **标题**：遵守平台字数上限，不加引号
- **配文**：一句话摘要（15-30 字）
- **备选标题**：2 条，风格不同
- **正文**：
  - 小红书 3-5 段短句，可带 emoji
  - 公众号 3-6 段，每段 60-120 字
  - 抖音 3-4 段分镜口播，每段以时间码开头（0-3s / 3-8s …）
  - B站 2-4 段，每段 40-80 字
- **互动引导**：一句评论区话术
- **封面文案**：kicker + 2 行主标题（每行 ≤8 字）+ 副标题
- **话题标签**：小红书 5-6 个不带 # 的话题词

## 示例（用户：咖啡、简约、日漫风格、下午的松弛感 → 小红书）

> **标题**：下午的咖啡，配满屏简约大字母
> **配文**：用一杯咖啡，接住整个下午的松弛感。
> **正文**：下午三点，阳光刚好斜斜落进窗台，杯壁浮起一层薄薄的水雾，像日漫里被放慢的半帧画面。
> 入口先是清爽的酸，紧接着一点点回甘。喝到一半，风把窗帘吹得轻轻晃，时间像被谁调慢了一档。
> 原来松弛感不用刻意找，一杯冰咖啡、一个没人打扰的下午就够了。
> **互动**：评论区聊聊，你下午喝咖啡时最爱发什么呆？
> **封面**：AFTERNOON COFFEE / 「咖啡与午后」「松弛的漫进窗」
> **话题**：#咖啡日常 #松弛感 #日漫风 #下午时光 #简约生活
